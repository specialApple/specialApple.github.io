智能指针

智能指针

在C++11中通过智能指针，不需要手动释放内存

  • std::unique_ptr

  • std::shared_ptr

  • std::weak_ptr

  • std::auto_ptr(已被废弃)

  • 智能指针是原始指针的封装，优点是自动分配内存，不用担心潜在的内存泄露

  • 智能指针只解决一部分问题，即独占/共享所有权指针的释放、传输

  • 智能指针没有从根本上解决C++内存安全问题，不加以注意依然会造成内存安全问题

unique_ptr

  • 在任何给定的时刻，只能有一个指针管理内存
  • 当指针超出作用域时，内存将自动释放
  • 该类型指针不可Copy，只可以Move
  • 三种创建方式
    • 通过已有裸指针创建
    • 通过new来创建
    • 通过std::make_unique创建 （推荐）
  • unique_ptr可以通过get（）获取地址
  • unique_ptr实现了->与*
    • 可以通过->调用成员函数
    • 可以通过*调用 dereferencing
Passing by value（按值传递）
  • 需要用 std::move 来转移内存所有权。
  • 如果参数直接传入 std::make_unique 语句（临时对象/右值），会自动转换为 Move
Passing by reference（按引用传递）
  • 如果设置参数为 const 则不能改变指向（例如不能调用 reset()）。
  • reset() 方法为智能指针清空方法（释放当前对象，将指针置空）。
Return by value（按值返回）

  • 指向一个 local object：可以直接在函数内 make_unique 并返回。C++ 的移动语义和返回值优化（RVO/NRVO）会安全地将资源转移给调用者，不会报错。

  • 可以用作链式函数：返回智能指针，结合返回自身引用的成员函数，可以实现类似 createCat()->setName(“Tom”) 的链式调用。

  • 传参：unique_ptr 只能移动。用 std::move 放弃所有权，或者传递临时对象。想借用但不转移所有权，用 const unique_ptr&。想修改指针本身（如 reset），用非 const 引用 unique_ptr&。

  • 返回：放心大胆地按值返回 unique_ptr（尤其是局部对象），C++ 的移动语义会保证性能和安全。

  • 避坑：对于返回的 unique_ptr，如果只在单条语句中链式调用（如 get()->func()），对象会在该语句结束时立即销毁。如果需要延长它的生命周期，请务必用一个具名变量把它接住。

shared_ptr

  • shared_ptr 计数指针，又称共享指针。
  • 与 unique_ptr 独占所有权不同，shared_ptr 可以共享数据。它通过内部的引用计数（Reference Count）机制来管理内存：每当多一个 shared_ptr 指向同一块内存，计数加一；每销毁一个，计数减一；当计数归零时，自动释放内存。
Passed by value（按值传递）
  • 会发生拷贝（copy）。
  • 函数内部计数器加一（因为多了一个 shared_ptr 指向该对象）
  • 函数执行完毕后，拷贝的指针销毁，计数器减一。
Passed by ref（按引用传递）
  • 不发生拷贝，不增加引用计数。
  • const 表示不可改变指向（即不能在函数内部调用 reset() 或重新赋值，但可以修改指向对象的内容）。
  • 通常推荐使用 const std::shared_ptr& 传参，既避免拷贝开销，又防止函数内部改变指针指向。
Returning by value（按值返回）
  • 安全返回局部对象：可以在函数内 make_shared 并安全返回。得益于 C++ 的移动语义和 RVO（返回值优化），这不会导致性能问题。
  • 引用计数的变化：返回时会拷贝/移动，接收变量后引用计数会反映当前的所有者数量。
  • 支持链式调用：可以结合返回 *this 引用的成员函数，实现链式调用。
  • 核心机制：共享所有权。靠引用计数管理内存（拷贝加一，销毁减一，归零释放）。
  • 创建方式：推荐 auto p = std::make_shared(参数);。
  • 与 unique_ptr 区别：unique_ptr 独占（只能 move），shared_ptr 共享（可以 copy）。
  • 函数传参：首选 const std::shared_ptr&（不增计数，无拷贝开销，保护指针指向）。
  • 按值返回：安全，支持链式调用。但不接收返回值时，临时对象遇分号立即销毁。
  • 致命陷阱：循环引用会导致内存泄漏。互相指向时，其中一方必须改用 std::weak_ptr。

shared_ptr 与 unique_ptr 的转换规则

  • 不能将 shared_ptr 转换为 unique_ptr
    • 原因：unique_ptr 是独占所有权，而 shared_ptr 是共享所有权（可能有多个指针指向同一块内存）。如果强行把 shared_ptr 变成 unique_ptr，其他共享该内存的指针就会悬空，导致双重释放等严重错误。C++ 标准直接禁止了这种转换。
  • unique_ptr 可以转换为 shared_ptr
    • 原因：unique_ptr 本身就是独占的，把所有权转移给 shared_ptr 是安全的。转换后，shared_ptr 接管该对象，引用计数变为 1。
    • 转换方式：必须通过 std::move 显式转移所有权。
    • 转换后状态：原 unique_ptr 变为 nullptr，不再拥有该对象

weak_ptr（弱引用指针）

  • 不拥有所有权：weak_ptr 指向由 std::shared_ptr 管理的对象，但不会增加引用计数（use_count 不变）。
  • 不能直接访问对象：不能使用 * 解引用，也不能使用 -> 调用成员函数。
  • 如何访问：必须通过 lock() 函数，将其提升（类型转换）为 std::shared_ptr，然后才能操作对象。
  • 解决循环引用问题（Cyclic Dependency Problem）：
    • 假设有两个类 A 和 B。A 中有一个 shared_ptr，B 中有一个 shared_ptr。
    • 当外部指针销毁时，A 内部的 B 和 B 内部的 A 互相指着对方，导致它们的引用计数永远无法归零，造成内存泄漏（析构函数永远不会被调用）。
    • 解决方案：将其中一方的 shared_ptr 改为 weak_ptr。这样它只“观察”对方，而不增加引用计数，打破循环。
